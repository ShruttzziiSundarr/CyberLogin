The one thing to remember

Every single message touches the Browser lifeline. The SP and IdP never open a direct connection. Every byte of trust travels through the browser — which is fully under the attacker's control. That is why the assertion must be signed, time-bounded, audience-restricted, and bound to the original request. Each field in a SAML assertion exists because of this one structural fact.

The structural difference from SAML

Watch steps 6 and 7 — they are green, back-channel only. The tokens never cross the browser. SAML solved the hostile-channel problem by hardening the document (signatures, audience restrictions, time windows). OIDC solved it by refusing to use the hostile channel for tokens at all. Both approaches work; they just distribute the complexity differently.

Watch the KDC lifeline go silent after step 4

The KDC is not involved in the actual service session. All trust was baked into the ticket at issuance. This makes Kerberos highly scalable — no KDC round-trip per resource access — but creates its revocation weakness: a ticket issued before an account is disabled remains valid until it expires. Ticket lifetime (default 10 hours in AD) is therefore a security control, not just a performance tuning parameter.

The key property

The engineer never sees the credential. The vault brokers access and the credential rotates when the session closes. A stolen session token is time-limited. A stolen standing password is not. The audit log captures keystrokes tied to the engineer's identity — not to the shared privileged account — which is what makes post-incident forensics possible.

Why RADIUS is still everywhere

RADIUS dates to 1991. It uses UDP, MD5-based message authentication, and a shared secret between the NAS and server. It is not impressive by modern cryptographic standards. It is also implemented in virtually every managed switch, VPN appliance, and wireless controller on earth, which means any enterprise network policy still routes through it regardless of what sits in front. Understanding RADIUS means understanding why zero-trust network access policies still need a RADIUS-compatible back-end.

System for Cross-domain Identity Management · RFC 7643/7644
Choose an event below to see how the IdP pushes lifecycle changes to connected apps.
SCIM vs SSO — different problems

SSO (SAML or OIDC) handles the moment of login — the user authenticates once and the assertion carries them across apps. SCIM handles account existence — it creates, updates, and removes the account so there is something to log into. Without SCIM, SSO relies on just-in-time provisioning (creating a bare account on first login) or manual admin work for every app. Without SSO, SCIM gives every app a correctly populated account but still needs its own login page. Both together is the baseline for modern enterprise identity.

Header · algorithm & key id
"alg""RS256"
Signing algorithm. Pin this in code — never trust what the token says here. none and HS256 algorithm confusion are the two classic attacks.
"kid""pF9-2mQxK7"
Key ID. Used to select the right public key from the JWKS endpoint. Treat as opaque — never use it to build file paths (path traversal) or SQL (injection).
"typ""JWT"
Token type. Informational only.
Payload · claims
"iss""https://login.microsoft…"
Issuer. Exact string match required. In multi-tenant Entra, also check tid — signature-valid tokens from any tenant will match without it.
"aud""4c9d1f7e-treasury-web"
Audience — must be your client_id. Cross-app token replay exploits a missing aud check.
"sub""a7f3e91c-4d22"
Subject. The account key is iss + sub together, never sub alone across issuers.
"nonce""n-0S6_WzA2Mj"
Replay protection. Generated per-request, stored server-side, compared once, consumed. Not the same as state (which protects the redirect, not the token).
"exp"1784285040
Expiry epoch. Also check auth_time for sensitive operations — exp only tells you the token is fresh, not that the human recently authenticated.

The signature covers exactly these two sections. Changing any byte in header or payload invalidates the signature.

Why not the implicit grant?

The implicit grant returned the access token directly in the redirect URL fragment — visible in browser history, referrer headers, and server logs. PKCE solves the same problem (no client secret) without the exposure. The implicit grant is deprecated. If you see it in a codebase, it is a migration task.
